Recommended flow

  1. Download while permissions and the hotkey are configured. Keep the existing seven setup steps.
  2. If transferred bytes stop increasing, show recovery status. Heartbeats alone do not prove progress.
  3. Retry transient failures automatically with bounded backoff. Keep Retry Now available. Never start two transfers for the same model.
  4. Unlock Dictation once speech is loaded. A writing failure must not block it.
  5. Keep the same state and controls in Settings › Models, including after closing setup or restarting Velora.

Resume must be honest

Reuse validated completed files. Resume partial files only if the transfer adapter safely supports byte ranges and unchanged file identity. Otherwise restart that file and explain why.

No indefinite spinner. Network, disk, verification and model-load failures get different messages and actions.

Approaches and trade-offs
  1. Recommended: one recovery coordinator. Automatic bounded retries, controlled cancellation, shared onboarding/Settings state, validated cache reuse and tested partial resume. Addresses startup and model switches.
  2. Smaller patch: expose failure and restart the engine. Faster to implement, but interrupts active work and does not solve silent model switches or persistent partial resume.
  3. Settings-only retry. Small UI change, but first-time users still encounter an unexplained setup screen. Not recommended.
Audit findings and scope
  1. OnboardingView.swift:9–18,523: no error state; required speech failure becomes a starting spinner during supervisor retries.
  2. server.py:1307: uncached writing recovery stops. Setup can finish, but writing remains unavailable without a visible explanation.
  3. SettingsModel.swift:929–941; server.py:3915: model-switch downloads have no progress UI; errors can close the connection silently.
  4. models.py:343: cache progress double-counts blob/snapshot links. Replace it with per-transfer unique-byte accounting.
  5. OnboardingWindowController.swift:56: closing setup marks onboarding complete. Settings must remain a direct recovery route.

Source inspections, not reproduced production incidents. Swift storage symlink counting and delayed hotkey handling during model switches still need runtime tests. A loading heartbeat watchdog alone cannot detect a live thread with no byte movement.

Proposed tuning: a 60 s byte-stall threshold; retries after 2, 5 and 15 s, then explicit failure. Tune against slow links and transport tests. Manual Retry Now bypasses backoff, not cache verification. Metadata and model loading have separate deadlines.

Keep one transfer owner per model/revision. A retry first stops and joins the old worker. Publish attempt IDs so stale events cannot overwrite the new state. Persist recoverable file identity and partial state, then replay the current snapshot on reconnect.

Restart Download asks for confirmation, stops the transfer and discards only that attempt's partial file. Completed validated files and other installed models remain. Disk errors do not retry endlessly. A failed model switch keeps the previous working model.

Required tests: mid-body disconnect and recovery; open socket with no bytes; quit/relaunch; concurrent retries; ignored Range and changed ETag; disk full; corrupt snapshot; slow verification/load; writing-only failure; model-switch failure without losing the old model or blocking commands.
