# Velora 0.18.0

Voice actions can now work in the background. Say "in TextEdit, type up my
packing list" and keep writing your email — Velora drives the other app's
window directly, without ever taking your cursor, focus, or keyboard.

- Works when the free, open-source [Cua Driver](https://cua.ai/cua-driver)
  is installed; Velora finds it automatically and starts it on demand. No
  new permission dialogs — the driver works under the Accessibility access
  Velora already has. Without the driver, actions behave exactly as before.
- Deliberately scoped: messaging apps and browsers still run in front, on
  the battle-tested foreground path — a message to a real person deserves
  eyes on the screen. Background delivery is for document-style apps.
- Every safety rule is unchanged: the same plan validation, the same
  send consent, the same budgets. Typing is verified by reading the target
  window back, and an ambiguous target refuses rather than guesses.
- New toggle under Settings → Voice actions → "Work in the background"
  (shown when the driver is installed; on by default).
- Privacy note: Velora sends nothing anywhere, as always. The Cua Driver
  itself ships with anonymous, content-free product telemetry enabled by
  default — run `cua-driver telemetry disable` in Terminal to turn it off.
  Velora only starts the driver when an action actually needs it, shuts down
  the one it started when you quit, and refuses to talk to anything that
  isn't genuinely Cua's driver. Leave the setting off if you would rather it
  never run at all.
- `velora ax-probe` now reports why a background action would or wouldn't
  work on the app in front of you.
- Under the hood: apps that were never activated expose no accessibility
  tree; Velora materializes it with at most one brief window flash per
  action, then works invisibly.
