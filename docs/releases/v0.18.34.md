# Velora 0.18.34

Action Mode keeps an already-open target app in the background while you use
Telegram or another app.

- Native controls use public macOS Accessibility actions bound to one exact
  process, window, and retained element. A complete native tree is required.
- Cua observes windows and verifies results. It no longer clicks, types, presses
  keys, launches apps, or changes focus during automatic execution.
- Text replaces the exact retained editable value and proves the same value by
  readback. Incomplete or screenshot-only trees stay read-only.
- Input in the target window cancels the transaction; Velora never retries it.
- If an Accessibility action activates the target, Velora restores the exact
  process and window the user was using. A concurrent user switch always wins.
- A target without an open window is refused instead of being cold-launched.
- Music play and pause use an exact-process app-native capability with playback
  state verification, without routing through the unrelated AX press reviewer.
- In-app requests cannot finish after merely opening their app; the planner
  must continue until the requested state has exact proof.
- Repeated Accessibility identities no longer consume the structured UI budget.
- When an app has several visible windows, a unique topmost current-Space
  window is pinned; missing or tied window order is still refused.
- The completion card opens the target app only when you click it.
