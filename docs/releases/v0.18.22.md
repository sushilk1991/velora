# Velora 0.18.22

Voice Actions can now find and focus message fields from an app's own
Accessibility tree, including Slack composers nested deep inside the window.
There is no Slack- or WhatsApp-specific layout recipe to keep patching.

- Before Velora types or sends a message, it re-checks the exact focused field
  and requires that field's own label to name the person or channel. A matching
  sidebar row or header is not enough.
- An incomplete Accessibility tree stops the action instead of letting it
  guess. Focusing a text field is distinct from pressing a button, and every
  indexed action gets a fresh screen read before the next step.
- Planning is split into bounded controller, navigation-review, completion,
  and recipient-check calls. If an inaccessible screen does not change, Velora
  stops after one fresh retry instead of repeatedly running the local model.
- Under memory pressure, Velora drops Action-only model state immediately and
  unloads the writing-model process after a short idle grace. Reloads are
  bounded, retryable, and cancellable; status and cancel commands remain
  responsive while the model warms up.
- The Action capsule now shows whether Velora is reading, planning, confirming
  a recipient, executing, or retrying. A failed action keeps a concrete reason
  and offers Retry Action.
- Public builds no longer contain the path to the machine that built them.
